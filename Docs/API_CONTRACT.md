# API contract

This document describes the interfaces OrgAtlas exposes, not implementation code. All endpoints are served by FastAPI over HTTPS and exchange JSON.

The coding-agent interface is specified separately in [MCP server design](MCP_SERVER.md); it is not a browser REST API. The MCP surface and this REST API share the same retrieval services and the same read-only boundary.

All routes are served under the `/api` prefix.

## Product endpoints

| Method | Path | Purpose | Response includes |
| --- | --- | --- | --- |
| `GET` | `/health` | Confirm API and graph connectivity | Service health only; no secrets |
| `POST` | `/ask` | Answer a relationship-based question | Answer, citations, evidence path, graph subgraph, follow-ups |
| `GET` | `/onboarding/{team_id}` | Generate or read a team onboarding guide | Ordered topics, people, services, reading, sources, subgraph |
| `GET` | `/entity/{entity_id}` | Inspect a selected graph entity | Entity summary, connections, ownership, sources |
| `GET` | `/decisions/{decision_id}` | Trace one decision to its evidence | Rationale, alternatives, deciders, incidents, sources, subgraph |
| `GET` | `/demo-prompts` | List reliable questions for the seeded graph | Prompt text, intent, expected entities |

## Repository ingestion

| Method | Path | Purpose | Response includes |
| --- | --- | --- | --- |
| `POST` | `/repos/ingest` | Start a scan of a public repository | Job id and accepted status |
| `GET` | `/repos/ingest/{job_id}` | Poll a scan | Stage messages, counts, job status |
| `GET` | `/repos` | List ingested repositories | Repository id, name, url, commit and file counts |

A scan runs in an isolated E2B sandbox that clones and parses only. The sandbox never receives graph or model credentials, and it clones no dependency repository. Declarations are extracted in the sandbox with tree-sitter; a file with no usable grammar, an unmapped language, or a parse error contributes no symbols rather than a partial list.

## Change forensics

| Method | Path | Purpose | Response includes |
| --- | --- | --- | --- |
| `GET` | `/repos/{repository_id}/brief` | Orientation brief for a repository | Hotspots, experienced contributors, dependent repositories, guidance |
| `GET` | `/repos/{repository_id}/churn` | Files that change most | Path, change count, test flag |
| `GET` | `/repos/{repository_id}/commits` | Recent commits in a repository, or under a `path_prefix` | Commit summaries |
| `GET` | `/repos/commit/{commit_id}` | One ingested commit with its files and provenance | Message, author, date, files, pull request |
| `GET` | `/repos/file/timeline` | Who changed a file and when | History, contributors, citations, subgraph |
| `GET` | `/repos/file/coupling` | Files that change alongside this one | Co-changing paths and advice |

## Authored and generated descriptions

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/repos/file/describe?file_id=…` | What a file's authors documented about it |
| `GET` | `/repos/file/symbols/{name}` | Explain one exported function, type, or method |

`file_id` is the graph node id of the form `repo_<name>::<path>`.

### Describe-file response fields

| Field | Description |
| --- | --- |
| `summary` | Documentation extracted from the file's own `//!`, `///`, headings, tables, or declarations |
| `symbols` | Public declaration names found in the file |
| `docs_source` | `module`, `item`, `declaration`, `heading`, `key`, `model`, `none`, `skipped_large`, `skipped_unreadable` |
| `docs_at_sha` | The revision the description was derived from |
| `stale` | True when the file changed after that revision |
| `staleness_reason` | Plain-language explanation of the staleness verdict |
| `provenance` | Whether the text was `authored` or generated by a `model`, with model name, generation time, input revision, trigger, prompt version, token usage, and any error |
| `raw_response` | The untouched provider response, retained for audit |

`docs_source` is what decides how the rest of the row should be read. `model` means a provider generated the text because the file's authors wrote nothing usable; `none` means no description exists. Binary files and files above the size cap are reported as skipped and are never sent to a model.

### Describe-symbol response fields

| Field | Description |
| --- | --- |
| `match_count` | How many declarations share the name |
| `matches[].signature` | The declaration up to its body |
| `matches[].doc_comment` | The documentation its authors wrote, or empty |
| `matches[].documented` | False when no doc comment exists. Never generated |
| `matches[].line` | One-based line in the scanned revision |
| `matches[].container` | Enclosing type, trait-qualified for `impl Trait for Type` |
| `matches[].visibility` | `pub`, `pub(crate)`, `public`, or `trait` for members of a public trait |
| `matches[].changes_since_docs` | Commits touching the file after the scan, so a line number is not presented as current when it has moved |
| `guidance` | What to do next, including a warning when nothing is documented |

An ambiguous name returns every match with its container rather than silently choosing one. Only exported declarations are recorded, so private helpers and paths excluded by the repository filters will not appear.

## Document ingestion

| Method | Path | Purpose | Returns |
| --- | --- | --- | --- |
| `POST` | `/docs` | Upload and ingest a PDF, `.md`, `.txt` or `.csv` | Job status and counts |
| `GET` | `/docs/ingest/{job_id}` | Poll a document job | Stage, counts, error |
| `GET` | `/docs` | List ingested documents | Title, kind, hash, summary |
| `POST` | `/docs/slack/ingest` | Ingest Slack history | Messages, attributed, linked |
| `GET` | `/docs/decisions/{decision_id}` | One decision with all evidence | Documents, people, quotes, metrics, commits, notes |

Upload is multipart with `file`, and optional `title`, `author`, `extract`.
`extract=false` parses and links without calling the model.

See [DOCUMENTS.md](DOCUMENTS.md) for the pipeline and the verification rules.

## Ingest job lifecycle

`POST /repos/ingest` returns immediately and the scan runs in the background. A client
polls `GET /repos/ingest/{job_id}` until `status` is terminal.

| `status` | Meaning | Terminal |
| --- | --- | --- |
| `queued` | Accepted, waiting for a sandbox | no |
| `cloning` | Sandbox creation, app sync, or git clone in progress | no |
| `parsing` | Walking history and extracting files, symbols, dependencies | no |
| `writing` | Committing batched graph updates | no |
| `describing` | Running the model fallback over files with no authored docs | no |
| `done` | Finished; the three counts below are final | yes |
| `failed` | Stopped; `error_message` says why | yes |

`commits_ingested`, `files_indexed`, and `identities_resolved` increment as work completes, so
they are meaningful mid-flight. `stage_detail` carries the scanner's own message and may be
updated without a status change.

## Error strategy

| Condition | Status | Client outcome |
| --- | --- | --- |
| Invalid question or context | `422` | Inline validation message |
| No matching graph evidence | `200` or `404` | Explicit "no evidence" result with suggested follow-up |
| File, symbol, or entity absent | `404` | Names the identifier and what to do about it |
| FalkorDB unreachable | `500` | Clear temporary-error state; never a fabricated answer |
| Nebius unavailable | `200` | Retrieved facts and sources without a generated narrative |

## Contract rules

- Never expose connection strings, provider keys, raw stack traces, or arbitrary Cypher execution.
- Keep graph payloads bounded; return only the answer-relevant subgraph.
- Preserve stable identifiers so the UI can select a citation and highlight its graph node.
- Report absence explicitly. An empty result must say what is missing rather than infer content.
- Distinguish authored text from generated text in every response that carries either.
- Version the API before making breaking changes.
