what is built and what is deliberately not, so the gap between design documents
and reality is visible in one place.

Update this whenever a milestone lands or an item below is closed.

## Delivered, in order

- Evidence-first ask/onboarding/decision surfaces over FalkorDB Cloud.
- Repository ingestion in an isolated E2B sandbox: clone, parse history, write batched graph updates. No credentials enter the sandbox and no dependency repository is cloned.
- Include/exclude filtering, injected from the host rather than resolved inside the clone.
- Change forensics: churn, file timelines, coupled files, commit provenance, dependency blast radius.
- Authored file descriptions extracted from a repository's own documentation.
- Function-level declarations parsed with tree-sitter across ten grammars.
- A model fallback that runs only where the authors wrote nothing usable, with full provenance.
- Read-only MCP context server with tools, resources, and prompts.
- LLM-first `/ask`: the model synthesizes an answer from retrieved packages and must cite its sources, with a deterministic graph-fact fallback when the provider fails or the answer cites nothing it was given.
- Document ingestion: upload a PDF, markdown or CSV, extract decisions, people, quotes and metrics with
  every claim checked against the sentence it came from, link them into the graph, and answer from all of it.
- A Slack bot so a developer or an agent can ask in the channel where the question already arises, and get
  a cited answer instead of a guess. Socket Mode, so it runs from a laptop with no public URL.
- `/ask` answering questions about the ingested repository, not only the fictional organisation. Terms
  are resolved against the graph in one round trip and the resolved node's label chooses between
  ownership, change impact, decisions, onboarding, declarations, files, and commit history.
- A Repositories view that shows real ingested repositories separately from the fictional seed, covers ingest progress, briefs, churn, file history and descriptions with provenance, symbol lookup, and declared dependencies.
- A filter-aware prune tool for removing graph nodes a current filter set would no longer admit.

## Open work, in priority order

### 0. Document extraction is slow and expensive
One document took 188s and 11,531 completion tokens, nearly all of it reasoning, because the
configured model is a reasoning model run over prose. This is workable for a demo and wrong for a
bulk load. `extract=false` skips it. A non-reasoning model for extraction would change both numbers
substantially and is the obvious next step.

### 0b. Stored descriptions still hold the old 400-character summaries
The extraction limit was raised to 5,000 characters and now cuts at a sentence
boundary, but the graph still holds summaries produced under the old limit. The
ingest cache keeps the finished summaries rather than the source text, so they
cannot be recomputed without re-running the ingest. Until that happens, a live
`describe_file` still returns a clipped description. This is the one item on this
list that a re-ingest closes outright.

### 0c. Two decisions about the same technology are not disambiguated
Asking about a Kafka-to-Redis migration while a seed decision about adopting Kafka also
mentions Kafka resolves to whichever candidate scores higher, and the seed one won in
practice. The answer still refused to overstate -- it said the premise was unsupported and
named what the evidence did show -- but it answered about the wrong decision. Resolving
across several same-topic decisions, rather than picking the best-scoring one, is the fix.

### 1. MCP authentication is not implemented
The `/mcp` route mounts only when `ENVIRONMENT` is `development`, is never added to the browser CORS allowlist, and startup fails loudly if `MCP_API_TOKEN` is set without a verifier. That is safe, but it means the surface cannot yet be exposed to a real remote agent. This is the only item that blocks a deployed coding-agent demo.

### 2. Ingested commits are reduced from 600 to 320
Commits whose files were *all* excluded by the filters are dropped entirely, so history touching only `.json`, `.js`, `.c`, or `.h` files is absent. This is a deliberate trade-off, not a defect, but it is a real reduction in coverage and should be a conscious choice rather than a surprise. Widening `include_globs`, or keeping filter-excluded commits with no file edges, would recover it.

### 3. No ingested commit is attributed to a seeded person
All 243 `AUTHORED` edges resolve to `ExternalIdentity`. Real contributors in a public repository do not share emails with fictional seeded employees, so this is expected behaviour. The consequence is that repository history shows contributors, never employees. Mapping some repositories onto seeded people would need a deliberate, stated rule.

### 4. Non-Rust grammars are only snippet-verified
Only Rust is validated against real repository files. The other nine grammars pass minimal snippet tests. The failure mode is *missing* symbols rather than wrong ones, but a language-specific parsing quirk could still cost coverage. A follow-up ingest of a polyglot repository would confirm or refute this.

### 5. Declaration `visibility` can be misread
Visibility is stored verbatim from the grammar, so values differ by language. The ingested Rust repository alone produces four: `pub`, `pub(crate)`, `pub(super)`, and `trait` for members of a public trait that carry no modifier of their own. A consumer filtering on a single literal will get partial results; treat every value here as exported at some level rather than assuming one spelling.

### 6. No call-graph extraction
`describe_symbol` answers "what is this and where does it live". It cannot answer "who calls this", which needs call edges rather than declarations. Listed as deferred in `MCP_SERVER.md`.

### 7. The payload cache is write-only
`cache_payload` writes the scan payload for inspection, but nothing reads it back, so a re-ingest always pays for a fresh sandbox run. The docstring claims otherwise and is wrong. Either wire the read path or correct the claim.

### 8. Undocumented symbols stay undocumented
By decision (ADR-012), a function with no doc comment reports that it has none. Roughly 72% of extracted declarations fall into this group. If judges expect every symbol explained, that gap is visible and intentional, and the honest response is to keep it.

### 9. Commit history is 600 deep
Ingested history stops at 600 commits, so anything older is invisible. Raising it costs sandbox time and graph size; the depth is a setting, not a hard limit.
